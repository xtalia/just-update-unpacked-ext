# Just Update Unpacked Ext

Личный навык для AI-агента: добавлять простое обновление в репозитории распакованных расширений Chrome / Chromium.

**Это пример подхода, не самостоятельный апдейтер и не менеджер пакетов.** Здесь нет готовой универсальной утилиты: агент читает навык, изучает конкретное расширение, создаёт подходящий скрипт и проверяет его в этом проекте.

## Что решает

Вместо «скачай ZIP → распакуй → замени файлы» пользователь запускает один файл обновления. Источник, ветка и папка расширения задаются при генерации. Первая загрузка распакованного расширения и последующий Reload в Chrome остаются ручными действиями.

Скачивать и распаковывать архив *внутри скрипта* нормально: пользователь не должен делать это вручную.

## Файлы

- [`SKILL.md`](SKILL.md) — инструкция для агента: что исследовать, что генерировать, как проверять и какие границы не переходить.
- [`references/example.md`](references/example.md) — пример запроса, структуры проекта и использования получившегося файла. Это сценарий, не готовая реализация.

## Использование в Hermes

Передай агенту эту ссылку и попроси установить навык в текущий профиль:

```text
Установи навык из https://github.com/xtalia/just-update-unpacked-ext
```

Либо помести `SKILL.md` и каталог `references/` в `skills/just-update-unpacked-ext/` активного Hermes-профиля. При заданном `HERMES_HOME` каталог skills находится внутри него. Не копируй файлы в другой профиль.

После установки:

```text
/just-update-unpacked-ext
Добавь в мой репозиторий расширения один update.cmd для Windows.
Путь к проекту: <путь к локальному репозиторию>.
Python допустим. Git у пользователя требовать не нужно.
Не публикуй изменения без отдельного запроса.
```

Навык сам по себе ничего не скачивает и не устанавливает в браузер. Он задаёт порядок работы агенту. Для другого агента достаточно прочитать `SKILL.md` и приложенный пример; команды установки зависят от его системы навыков.

## Принципы

- **Одна задача:** добавить обновление одному расширению, без GUI, фонового сервиса или реестра пакетов.
- **Один запускаемый файл:** `update.cmd`, `update.ps1`, `update.sh` или `update.command` под нужную платформу, а не обязательный набор соседних скриптов.
- **Зависимости честно:** по умолчанию Python 3 и стандартная библиотека, без pip. Статический код можно встроить в запускной файл; Python всё равно нужен. Если выбран Git, это явно указано в Quick Start.
- **Сначала проверка, затем замена:** фиксированный источник и ревизия, валидация снимка, резервная копия, восстановление при ошибке.
- **Не трогать чужое:** не очищать произвольную папку, не стирать локальные изменения и не менять настройки профиля Chrome.
- **Стабильный путь:** расширение остаётся в той же папке после обновления.
- **Без скрытой сборки:** если в репозитории нет готового расширения, агент сообщает об этом, а не запускает произвольные скачанные команды.
- **Реальные проверки:** изолированные сценарии установки и обновления, ошибки и восстановление; каждый обещанный запускной файл проверяется на своей ОС.

Это требования к будущим генерируемым скриптам, **не утверждение, что в этом репозитории уже есть протестированные Windows/macOS/Linux-апдейтеры**.

## За рамками

- Автоматический reload через отдельное браузерное расширение или Native Messaging.
- Сборка любого произвольного проекта.
- Автоматическая смена числовой версии расширения по коммиту. При необходимости SHA можно отдельно показывать через `version_name`.
- Менеджер нескольких распакованных расширений.

## Статус

Навык и пример. Готовый исполняемый апдейтер в этот репозиторий не входит. Проверка конкретного расширения выполняется при применении навыка к его проекту.
